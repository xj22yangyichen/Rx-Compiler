# 方法调用表达式

r[expr.method.syntax]
```grammar,expressions
MethodCallExpression -> Expression `.` PathExprSegment `(` CallParams? `)`
```

方法调用给出接收者表达式、方法标识符以及用括号包围的实参列表。最后一个实参后可以有一个可选的尾随逗号。

[PathExprSegment] 提供共用的路径段语法。方法使用其标识符，并可在 Rust 允许的位置附带可选的生命周期实参。[路径解析](../paths.md#path-resolution)规定这些实参和生命周期有效性保证。方法段上的类型实参会导致编译错误。

<a id="method-lookup"></a>
## 方法查找

查找前必须已知接收者类型。方法调用按以下方式确定接收者调整：

1. 从接收者表达式的类型开始，反复解引用引用和 `Box`，按顺序记录每个类型。`Vec` 不会增加解引用步骤。
2. 在每个记录的类型 `T` 之后，立即插入 `&T` 和 `&mut T` 作为候选接收者类型。
3. 按该顺序访问候选接收者类型。对于每个候选：
   - 如果有多个不同的方法匹配该候选（例如接收者类型相同的固有方法和派生的内建 `Clone` 方法），则该调用导致未定义行为。
   - 如果恰好有一个方法匹配该候选，则选择它并终止候选搜索。搜索包括固有方法、可用的内建 `Clone` 方法以及规定的数组和容器方法。
   - 如果没有方法匹配该候选，则继续处理列表中的下一个候选。
4. 如果列表中没有候选匹配任何方法，则编译失败并产生编译错误。实参类型、预期结果类型和接收者可变性都不用于筛选方法是否匹配。
5. 对所选方法，应用该候选所需的解引用和借用；已有的可变引用接收者可以根据[普通引用规则](../types.md#mutable-reference-reborrowing)进行重借用。然后检查接收者可变性和普通实参。如果任何检查失败，则编译失败并产生编译错误，但仍受单独的所有权和生命周期测试保证约束。

测试排除了同一候选上存在竞争方法的情况；编译器无需检测这种情况，也无需实现 Rust 中固有方法优先于 Trait 方法的规则。重复的固有声明仍然属于[名称错误](../names.md#name-collisions)；位于接收者候选列表之外的不相关类型上的方法不会参与竞争。

<details>
<summary>接收者与 clone 示例</summary>

对于 `Box<S>`，候选接收者类型依次为 `Box<S>`、`&Box<S>`、`&mut Box<S>`、`S`、`&S` 和 `&mut S`。对于 `S` 上以 `&self` 为参数的唯一匹配方法，在 box 上调用它会解引用到 `S` 并借用该位置。根据[位置规则](../expressions.md#places-and-values)，`&mut self` 方法要求对到达的 `S` 位置具有可变访问权限。

如果 `S` 派生了 `Clone` 且没有固有的 `clone` 方法，则在 `s: S` 上调用 `s.clone()` 会匹配候选 `&S` 并返回 `S`。同样，在 `r: &S` 上调用 `r.clone()` 会直接匹配候选 `&S`，无需检查 `&&S`，并返回 `S`。

但是，如果 `S` 派生了 `Clone`，同时又声明了一个名为 `clone` 的固有方法（如 `fn clone(&self)`），则在 `s: S` 上调用 `s.clone()` 会导致未定义行为，因为固有方法和派生的 Trait 方法都匹配候选 `&S`。

类似地，对于 `b: Box<i32>`，候选 `&Box<i32>` 会在搜索到 `i32` 的候选之前匹配 `Box::<i32>::clone`，从而将容器克隆为一个新的 `Box<i32>`。

</details>

显式调用 `Type::method(receiver, ...)` 会选择该类型的关联操作，并使用[普通实参强制转换](call-expr.md)，而不进行接收者查找或自动借用。如果该确切类型上的固有方法与内建方法同名，则选择固有方法。可用的内建操作参见[内建 Trait](../builtin-traits.md#clone)和[堆](../heap.md)。
